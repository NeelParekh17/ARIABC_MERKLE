Inside one replica: parallel backends, one ordered gate

Backends speculate in parallel, then pass the gate in sequence order: validate against everything published since their snapshot, publish their footprint (P), apply heap and Merkle writes, and commit; the finalized prefix (C) only advances contiguously. Ordered physical fallback: the eight reasons

shm_transaction.h

Each guard raises internal BC010 before its statement takes a speculative effect. The whole unpublished attempt is discarded; the retry waits for its turn and for every predecessor to commit, then runs ordinary SQL. Case “tx 10 needs ordered physical fallback” above plays this route.

    Outcome rules that changed since the last review

    4921f6a5
    • One top-level statement. Empty or multi-statement requests fail with 0A000 before anything runs; the failure is a deterministic outcome in its slot.
    • Deferred UPDATE checks unique indexes. The index phase runs with unique checking on; a duplicate surfaces at apply time and follows the post-publication settle rules, never a SQL rerun.
    • Partial indexes honour their predicate. A new tuple outside the WHERE clause gets no entry.
    • Stale errors re-run. An error raised on a snapshot that may miss predecessors (baseline < s−1) takes BC010 instead of being finalized; only an error on the ordered physical run is final (committed in 56fc1552).
    • EXCEPTION blocks never trap BC010. The guard fires at block entry; the worker's post-SQL check (dt_opf_caught) remains as defence in depth.

    Step-by-step versions of each rule are in the Determinism explorer.

    Merkle integrity, live

    A working model of the index code with 4 partitions, fanout 4 (2 key-hash bits per level), split above 8 rows and merge at 2 or fewer. Row hashes are 32-bit stand-ins for BLAKE3-256, and nodes hold their AdHash sum: the engine adds 256-bit values mod 2^256, the model adds 32-bit values mod 2^32.     Why AdHash replaced XOR

    6b19ff92

    Add identical rows and compare the two aggregates. XOR is its own inverse, so every identical pair cancels.

    • INSERT adds H, DELETE adds −H (merkle_hash_negate), a same-leaf UPDATE adds H(new) − H(old); carry crosses every byte of the little-endian value.
    • Index format 11 refuses format-10 (XOR) nodes with a REINDEX hint; merkle_rebuild_legacy_indexes() rebuilds and verifies them. Never mix XOR baselines with AdHash nodes.
    • A multiset checksum, not an adversarial commitment: equal roots are evidence, not proof.

    What merkle_verify() checks

    merkleverify.c
    1. Format. The metapage must be the current format, even on an empty heap.merkle_open_consistent_index → merkle_read_meta
    2. ① Hash. Σ of every visible heap row hash = Σ of the partition root hashes.WARNING “mismatch … stored / heap_sum”
    3. ② Count. Heap row count = Σ of the root tuple_counts (only after ① matched).WARNING “count mismatch roots / heap”
    4. ③ Internal nodes. Every non-leaf node = Σ of its direct children, hash and count, in (partition, prefix, node) order.WARNING “structural mismatch … children_sum”

    Not checked: that each row sits in the leaf its key routes to, or errors that compensate each other so every sum stays equal.

    Supported operations and DDL boundaries

    4921f6a5
    • Supported: INSERT, UPDATE (same leaf or route move), DELETE, COPY, savepoints and rollback, REINDEX, deterministic and plain transactions. Maintenance is synchronous: leaves and every ancestor through the partition root are exact at commit.
    • Geometry: fanout must be a power of two from 2 to 256; partitions 1 to 32,767. Split defaults to 1,024 at fanout 32, merge to split ÷ 4.
    • Index shape: expression and partial Merkle indexes are rejected. Merkle serves no scans and enforces no uniqueness: keep a primary key for lookups.
    • Private backing table: nodes live in ariabc_internal.merkle_node_<schema>_<table>, an ordinary MVCC + WAL relation. Its name must fit NAMEDATALEN with room for _prefix_idx / _root_idx and must not already belong to another table.
    • Names are fixed: renaming a table with a Merkle index, moving it to another schema, or renaming its schema is refused, because the backing name derives from them.

    Access: the backing table is ordinary catalog-visible SQL storage. Nothing here protects it from a superuser or table owner; integrity comes from comparing replicas and recomputing from the heap.

    06 · Integrity

    Online recovery: repair one replica while the cluster keeps committing

    Detection quarantines the minority replica, a donor exports an exact snapshot at a Raft boundary (CUT), the damaged replica repairs only the differing Merkle ranges, rebases its sequence and replays its own Raft log. Recovery is off in every throughput and latency run (recovery_mode=off).
