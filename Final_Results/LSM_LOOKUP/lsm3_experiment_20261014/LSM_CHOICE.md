# LSM choice

Selected Postgres Pro lsm3, upstream commit 3bac10420e7738ddbd78e0eea7e3967afdd35aac. Source URL: https://github.com/postgrespro/lsm3 . The complete upstream source is in repo/contrib/lsm3, with upstream commit and file hashes in evidence/lsm3_commit.txt and evidence/lsm3_upstream.sha256. This is a three-B-tree LSM design: inserts enter one active top, a second top permits concurrent background merges, and scans merge both tops with the base.

The fork's 13devel label predates final PG13 B-tree deduplication, AM fields, and QueryCompletion API. PGXS also needs the fork's source include directory because its installed server headers omit bcdb/globals.h. Build with PG_CPPFLAGS="-DARIABC_PRE13 -I.../src/src/include". lsm3_compatibility.patch excludes unsupported deduplication/AM fields and opclass support-4 functions, uses the old metapage/utility signatures, and adds parse transformation before defining expression top indexes. No PostgreSQL engine algorithm changes.

Additional upstream defects were corrected: lsm3_top_index_size accidentally called its relation-size helper twice, opening a block count as an OID (runtime OID 7); the background-worker registration retry used || instead of &&, causing an unnecessary minimum one-second wait and potentially unbounded retries after worker failure. The patch fixes both. It also reserves a zero-based insert position under the existing spinlock and uses that position for the periodic size check. Previously, concurrent insert callbacks could advance the shared counter across a 65,536 boundary between unlocked checks, skipping compaction. The check period is unchanged; no size check or merge is disabled. A fourth upstream defect affected preloaded det as well: the DROP INDEX hook ignored IF EXISTS by calling relation_openrv. It now uses relation_openrv_extended with drop->missing_ok and skips absent relations. Claude rebuilt the library and verified both missing and existing LSM-index DROP cases before restarting smoke at 14:59Z. Failed build/runtime attempts are retained.

Measurement configuration: shared_preload_libraries='lsm3' in ALL modes, lsm3.top_index_size=1024 KiB, per-index top_index_size=1024, max_worker_processes=32, default max_indexes=1024. One MiB keeps the active write index small relative to 32 MiB shared buffers; two top trees can together exceed one MiB during compaction. The unmodified 65,536-insert size-check period can overshoot the configured threshold and means a 20,000-statement workload may complete without a merge. Both physical top sizes, requested merge count, completion log count, compaction drain time, and post-drain I/O are recorded. The user cancelled sustained compaction measurements. Report short-run merge counts and top sizes without any claim about surviving compaction.

Small SQL correctness, actual det server/gateway tests, normalized 100M baselines and all 50 final post-workload Merkle verifications passed. The complete campaign contains smoke 3 plus ff90 72. Every one of the 24 LSM grid runs requested/completed zero merges. Tops ended at 8,192/8,192 bytes for θ0 and θ0.99/w1, and 16,384/8,192 bytes for θ0.99/w4,w8,w16. The 1 MiB limit was never approached. RESULTS.md reports mixed small TPS changes with almost no lookup insertions; there is no sustained-compaction performance conclusion.
